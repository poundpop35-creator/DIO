# DPTC · ทะเบียนครุภัณฑ์คอมพิวเตอร์และจอ

แอปสำหรับทะเบียน **2569+จอ** ดูภาพรวม แยกกลุ่ม/ฝ่าย ค้นหารายการ บันทึกผลทดแทนคอมกับจอแยกกัน และจัดทำแผนตามอายุ 2570–2575

สำหรับ Vercel มี `vercel.json` กำหนด build และโฟลเดอร์เผยแพร่ `dist/` โดยตรง เผยแพร่เฉพาะหน้าทดลองและสัญญาอนุญาตฟอนต์ การเชื่อมชีตจริงยังใช้ Apps Script ตามขั้นตอนด้านล่าง

## ทดลองหน้าจอ

เปิด `index.html` ในเบราว์เซอร์ได้ทันที ไม่ต้องติดตั้งไลบรารี หรือรัน:

```sh
npm start
# เปิด http://localhost:4173
```

หน้าทดลองใช้ **ข้อมูลสมมติ** ไม่มีชื่อบุคลากร รหัสครุภัณฑ์จริง หรือรหัสเข้าใช้งาน การแก้ไขเก็บในหน่วยความจำของหน้านั้นเท่านั้น รีโหลดแล้วเริ่มใหม่ ตัวเลขชุดตัวอย่างอ้างอิงโครงสร้างฐานปี 2569 และไม่ใช่ข้อมูลสดจากชีต

- ภาพรวม: PC ฟ้า / NB ม่วง / จอเขียวอมฟ้า
- ทะเบียน: ค้นหา กรองฝ่าย/ประเภท เปิดรายละเอียด เพิ่มและแก้ไขรายการ
- กลุ่ม/ฝ่าย: จำนวน PC, NB, จอ และเปิดทะเบียนเฉพาะฝ่าย
- แผนตามอายุ: ตารางเดียว 6 ปี พร้อมผลรวมครั้งเดียว
- ตรวจสอบข้อมูล: รหัสจอ ปีซื้อ และปีที่ควรยืนยัน
- ส่งออก CSV ที่ป้องกันข้อความถูกตีความเป็นสูตร และพิมพ์แผนเป็น PDF

## หลักการนับ

| รายการ                 | วิธีคิด                                                        |
| ---------------------- | -------------------------------------------------------------- |
| อายุ                   | ปี พ.ศ. ปัจจุบันตามเวลาไทย − ปีซื้อ; ใช้ปีเต็ม ไม่คำนวณเป็นวัน |
| อายุไม่เกิน 5 ปี       | ปกติ                                                           |
| อายุเกิน 5 ปี          | เข้าเกณฑ์อายุพิจารณาทดแทน; ปีแรก = ปีซื้อ + 6                  |
| PC                     | รวม PC (ห้องสมุด)                                              |
| จอแยก                  | นับรหัสรูปแบบ `7440-006-xx-xx-xxxx`; รวมจอแยกที่ใช้กับ NB      |
| ไม่มีรหัสจอ            | ไม่เดาว่ามีจอ; แสดงให้ตรวจข้อมูล                               |
| มีปีซื้อจอแต่ไม่มีรหัส | คำนวณอายุได้ แต่ยังไม่นับเป็นจอที่ตรวจรหัสผ่าน                 |
| สถานะจอ                | เจ้าหน้าที่เลือก ปกติ / ชำรุด / อยู่ระหว่างซ่อม                |
| จอเกิน 5 ปีที่ยังปกติ  | เตือนว่าเข้าเกณฑ์อายุ แต่ไม่เปลี่ยนเป็นรายการต้องซื้อใหม่      |
| ผลทดแทน                | บันทึกแยกคอมและจอ; ไม่บังคับทดแทนพร้อมกัน                      |

แผนเป็น **จำนวนเข้าเกณฑ์อายุจากทะเบียน** ไม่ใช่วงเงินหรือคำอนุมัติซื้อ และยังไม่หักผลดำเนินการทดแทนออกจากแผน เพื่อไม่ให้ยอดอายุปะปนกับยอดคำขอซื้อ สถานะที่ต้องติดตามบนภาพรวมแยกกรองผลทดแทนแล้ว/ไม่ทดแทนออก

## เชื่อมชีตจริงผ่าน Google Apps Script

โค้ดพร้อมติดตั้ง แต่ยังต้องตั้งค่าบัญชีและเผยแพร่ Web app ในบัญชี Google ที่มีสิทธิ์ชีต การเปิด `index.html` บน GitHub อย่างเดียวจะไม่เชื่อมชีต

1. เปิด Google Sheet เดิม → **ส่วนขยาย → Apps Script** หรือสร้างโปรเจกต์ Apps Script แยกที่ผู้ติดตั้งมีสิทธิ์แก้ไขชีต
2. คัดลอก `apps-script/Code.gs` เป็นไฟล์ Code และ `apps-script/Index.html` เป็นไฟล์ HTML ชื่อ **Index** (ตัว I ใหญ่) ใช้ `apps-script/appsscript.json` สำหรับ manifest ตั้งเขตเวลา `Asia/Bangkok`
3. ใน **Project Settings → Script Properties** เพิ่ม:

   | Property            | ค่า                                                    |
   | ------------------- | ------------------------------------------------------ |
   | `SPREADSHEET_ID`    | ID ของไฟล์ Google Sheet เดิม                           |
   | `SHEET_NAME`        | `2569+จอ`                                              |
   | `ACCESS_CODE_SETUP` | JSON บัญชีตามตัวอย่างด้านล่าง โดยเปลี่ยนรหัสเองทั้งหมด |

   ```json
   [
     {
       "code": "REPLACE-WITH-A-RANDOM-ADMIN-CODE",
       "role": "admin",
       "department": "*",
       "label": "ผู้ดูแลระบบ"
     },
     {
       "code": "REPLACE-WITH-A-DIFFERENT-STAFF-CODE",
       "role": "staff",
       "department": "ฝ่ายบริหารทั่วไป",
       "label": "เจ้าหน้าที่ฝ่ายบริหารทั่วไป"
     }
   ]
   ```

   รหัสแต่ละบัญชีต้องไม่ซ้ำกันและยาวอย่างน้อย 16 ตัวอักษร ใช้รหัสสุ่มและส่งให้ผู้ใช้เป็นการส่วนตัว ไม่ใส่รหัสใน GitHub หรือ HTML สามารถเพิ่มบัญชีอีก 3 กลุ่มด้วยชื่อฝ่ายตรงกับชีต

4. เลือกฟังก์ชัน `configureAccess_` ใน Apps Script editor แล้วกด Run และอนุญาตสิทธิ์ ฟังก์ชันจะแปลงรหัสเป็นแฮชใน `ACCESS_RULES` และลบ `ACCESS_CODE_SETUP` ที่เป็นข้อความเดิม
5. เลือก **Deploy → New deployment → Web app** กำหนด Execute as เป็นบัญชีผู้ดูแลชีต และจำกัดผู้เข้าถึงในองค์กรหากบัญชีรองรับ จากนั้นเปิด URL `/exec` ที่ได้
6. เข้าใช้งานด้วยรหัสที่ตั้งไว้ แอปจะอ่านชีตจริงและแสดงปุ่มเปิด Google Sheet โดยอัตโนมัติ เมื่ออัปเดตโค้ดภายหลัง ให้แก้ deployment เป็นเวอร์ชันใหม่

`admin` จัดการทุกฝ่าย, `staff` อ่าน/แก้ไขเฉพาะฝ่ายตนเอง, `viewer` ดูอย่างเดียวและกำหนดขอบเขตฝ่ายได้ การเปิดลิงก์ Google Sheet ยังขึ้นกับสิทธิ์ Google ของผู้ใช้เอง รหัสเข้าแอปไม่ได้เพิ่มสิทธิ์ชีต

### ความเข้ากันได้กับชีตเดิม

หัวคอลัมน์ต้องอยู่แถว 1 แอปค้นคอลัมน์ด้วยชื่อ ไม่ยึดตำแหน่ง จึงย้ายคอลัมน์ได้ รองรับชื่อสถานะคอม `สถานะ pc/nb` และชื่อเดิมที่ระบุใน `DPTC_HEADERS`

คอลัมน์ที่ต้องมี:

- ลำดับ, ประเภท, ผู้รับผิดชอบ, กลุ่ม/ฝ่าย, AMS, ปีที่จัดซื้อ, อายุ PC/NB, สถานะ pc/nb, ผลดำเนินการทดแทน
- จอ, ปีที่จัดซื้อจอ, อายุจอ, สถานะจอ, ผลดำเนินการทดแทนจอ
- หมายเหตุ, เหตุผลความจำเป็นในการขอซื้อ

รองรับชื่อปีซื้อ `ปีที่จัดซื้อ (PC/NB)` และชื่อทดแทนบางแบบด้วย ดูรายการทั้งหมดใน `DPTC_HEADERS` หากมีสองคอลัมน์ที่มีความหมายเดียวกัน แอปจะหยุดให้ตรวจแทนการเดาคอลัมน์

สถานะจอและผลทดแทนทั้งสองช่องต้องเป็นช่องกรอก ไม่ใช่สูตร แอปบันทึกเฉพาะช่องที่แก้ไขได้ แล้วคำนวณสูตรอายุและสถานะคอมของแถวนั้นใหม่ ไม่เขียนทับคอลัมน์ตรวจสอบข้อมูล/Firewall/การส่งมอบ การเพิ่มแถวใช้พื้นที่ว่างที่เตรียมไว้ในชีต และไม่ขยายแถวโดยอัตโนมัติเพื่อรักษาสูตรแยกฝ่าย

มีการล็อกตอนบันทึก ตรวจข้อมูลถูกแก้พร้อมกัน ป้องกันรหัสครุภัณฑ์ซ้ำ และบันทึกประวัติใน `Log` ไม่มีปุ่มลบแถว หากบุคคลแก้ชีตโดยตรงพร้อมกับแอป ควรรีเฟรชก่อนบันทึกเสมอ

## พัฒนาและตรวจสอบ

ต้องใช้ Node.js 20 ขึ้นไป ไม่มี dependencies สำหรับ runtime หรือ unit tests

```sh
npm test
npm run build
```

แก้ไฟล์ใน `web/` แล้ว build ใหม่ อย่าแก้ไฟล์รวมโดยตรง สคริปต์สร้างทั้ง `index.html` และ `apps-script/Index.html` จากต้นฉบับชุดเดียวกัน

- `web/domain.js` — กฎการนับและคำนวณ
- `web/app.js`, `web/styles.css` — หน้าจอและการทำงาน
- `web/demo.js` — ข้อมูลตัวอย่างนิรนาม
- `apps-script/Code.gs` — อ่าน/เขียนชีต ตรวจสิทธิ์ และบันทึกประวัติ
- `tests/` — ตรวจยอดแยกฝ่าย แผน 6 ปี ขอบเขตอายุ และการบันทึกผ่าน backend จำลอง

ไม่เก็บ Script Properties, `.clasp.json`, `.env`, ข้อมูลจริง หรือรหัสเข้าใช้งานใน repository นี้
