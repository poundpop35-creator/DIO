# DPTC · ทะเบียนครุภัณฑ์คอมพิวเตอร์และจอ

แอปสำหรับทะเบียน **2569+จอ** ดูภาพรวม แยกกลุ่ม/ฝ่าย ค้นหารายการ บันทึกผลทดแทนคอมกับจอแยกกัน และจัดทำแผนตามอายุ 2570–2575

สำหรับ Vercel มี `vercel.json` กำหนด build และโฟลเดอร์เผยแพร่ `dist/` โดยตรง เผยแพร่เฉพาะหน้าทดลองและสัญญาอนุญาตฟอนต์ การเชื่อมชีตจริงยังใช้ Apps Script ตามขั้นตอนด้านล่าง

## หน้าเว็บ (ข้อมูลจริง)

เปิด `index.html` หรือ https://dio-pc-nb.vercel.app ได้ทันที หรือรัน `npm start` แล้วเปิด http://localhost:4173

หน้าเว็บสาธารณะแสดง **ข้อมูลจริงจากชีต `2569+จอ`** (ไฟล์ `web/snapshot.js`) ได้แก่ เลข AMS รหัสจอ ปีซื้อ กลุ่ม/ฝ่าย สถานะ และหมายเหตุ เป็นแบบ **ดูอย่างเดียว** ส่วนชื่อ-นามสกุลบุคลากรไม่ถูกเผยแพร่บนหน้าสาธารณะ (ดูในชีต หรือในแอปผ่าน Apps Script ที่ต้องใส่รหัส) ตัวเลขตรงกับแท็บ "แผนทดแทนครุภัณฑ์" ของชีต: คอม 57 / PC 28 / NB 29 / จอ 30

เมื่อข้อมูลในชีตเปลี่ยน ให้อัปเดต `web/snapshot.js` (และ `SNAPSHOT_LABEL`) แล้ว `npm run build` อีกครั้ง

- สีประเภท: PC น้ำเงิน / NB ม่วง / จอ เขียวอมฟ้า ใช้เหมือนกันทุกหน้า
- สีสถานะ: เขียว = ปกติ / เหลือง = ต้องพิจารณาหรือตรวจข้อมูล / แดง = ชำรุด (แถบสีหน้าแต่ละแถว)
- ภาพรวม: ตัวเลขหลัก + ไทล์ "สิ่งที่ต้องดำเนินการ" กดแล้วไปยังรายการทันที
- ทะเบียน: ค้นหา กรองฝ่าย/ประเภท สลับคอม/จอ บนมือถือแสดงเป็นการ์ด
- กลุ่ม/ฝ่าย, แผนตามอายุ 2570–2575 (แถบกราฟ + ไฮไลต์ปีสูงสุด), ตรวจสอบข้อมูล
- ส่งออก CSV ที่ป้องกันข้อความถูกตีความเป็นสูตร และพิมพ์แผนเป็น PDF

## เชื่อมชีตจริงผ่าน Google Apps Script

โค้ดพร้อมติดตั้ง แต่ยังต้องตั้งค่าบัญชีและเผยแพร่ Web app ในบัญชี Google ที่มีสิทธิ์ชีต การเปิด `index.html` บน GitHub อย่างเดียวจะไม่เชื่อมชีต

1. เปิด Google Sheet เดิม → **ส่วนขยาย → Apps Script** หรือสร้างโปรเจกต์ Apps Script แยกที่ผู้ติดตั้งมีสิทธิ์แก้ไขชีต
2. คัดลอก `apps-script/Code.gs` เป็นไฟล์ Code และ `apps-script/Index.html` เป็นไฟล์ HTML ชื่อ **Index** (ตัว I ใหญ่) ใช้ `apps-script/appsscript.json` สำหรับ manifest ตั้งเขตเวลา `Asia/Bangkok`
3. ใน **Project Settings → Script Properties** เพิ่ม:

   | Property            | ค่า                                                    |
   | ------------------- | ------------------------------------------------------ |
   | `SPREADSHEET_ID`    | ID ของไฟล์ Google Sheet เดิม                           |
   | `SHEET_NAME`        | `2569+จอ`                                              |
   | `ACCESS_CODE_SETUP` | JSON บัญชีตามตัวอย่างด้านล่าง โดยเปลี่ยนรหัสเองทั้งหมด |
   | `OPEN_ACCESS`       | (ไม่บังคับ) `true` = ไม่ต้องใส่รหัส ใครมีลิงก์ `/exec` ดูและแก้ได้ทุกฝ่าย |

   ถ้าตั้ง `OPEN_ACCESS` = `true` ไม่ต้องทำขั้น `ACCESS_CODE_SETUP` / ข้อ 4 ลบหรือเปลี่ยนเป็น `false` เมื่อต้องการกลับไปใช้รหัส (มีผลทันที ไม่ต้อง deploy ใหม่) ทุกการแก้ไขยังบันทึกใน `Log`

   ```json
   [
     {
       "code": "REPLACE-WITH-A-RANDOM-ADMIN-CODE",
       "role": "admin",
       "department": "*",
       "label": "ผู้ดูแลระบบ"
     },
     {
       "code": "REPLACE-WITH-A-DIFFERENT-STAFF-CODE",
       "role": "staff",
       "department": "ฝ่ายบริหารทั่วไป",
       "label": "เจ้าหน้าที่ฝ่ายบริหารทั่วไป"
     }
   ]
   ```

   รหัสแต่ละบัญชีต้องไม่ซ้ำกันและยาวอย่างน้อย 16 ตัวอักษร ใช้รหัสสุ่มและส่งให้ผู้ใช้เป็นการส่วนตัว ไม่ใส่รหัสใน GitHub หรือ HTML สามารถเพิ่มบัญชีอีก 3 กลุ่มด้วยชื่อฝ่ายตรงกับชีต

4. ฟังก์ชัน `configureAccess_` ไม่แสดงในเมนู Run ของ editor ให้เพิ่มบรรทัด `function setupAccess() { configureAccess_(); }` ท้ายไฟล์ชั่วคราว Run `setupAccess` และอนุญาตสิทธิ์ แล้วลบบรรทัดนั้นทิ้ง ฟังก์ชันจะแปลงรหัสเป็นแฮชใน `ACCESS_RULES` และลบ `ACCESS_CODE_SETUP` ที่เป็นข้อความเดิม (จดรหัสไว้ก่อน ดูย้อนหลังไม่ได้)
5. เลือก **Deploy → New deployment → Web app** กำหนด Execute as เป็นบัญชีผู้ดูแลชีต และจำกัดผู้เข้าถึงในองค์กรหากบัญชีรองรับ จากนั้นเปิด URL `/exec` ที่ได้
6. เข้าใช้งานด้วยรหัสที่ตั้งไว้ แอปจะอ่านชีตจริงและแสดงปุ่มเปิด Google Sheet โดยอัตโนมัติ เมื่ออัปเดตโค้ดภายหลัง ให้แก้ deployment เป็นเวอร์ชันใหม่

`admin` จัดการทุกฝ่าย, `staff` อ่าน/แก้ไขเฉพาะฝ่ายตนเอง, `viewer` ดูอย่างเดียวและกำหนดขอบเขตฝ่ายได้ การเปิดลิงก์ Google Sheet ยังขึ้นกับสิทธิ์ Google ของผู้ใช้เอง รหัสเข้าแอปไม่ได้เพิ่มสิทธิ์ชีต

### ความเข้ากันได้กับชีตเดิม

หัวคอลัมน์ต้องอยู่แถว 1 แอปค้นคอลัมน์ด้วยชื่อ ไม่ยึดตำแหน่ง จึงย้ายคอลัมน์ได้ และรับหัวที่มีคำอธิบายต่อท้าย เช่น `ปีที่จัดซื้อจอ (ถ้ามี)` ชีต `Log` บันทึกตามชื่อหัวคอลัมน์ที่มีอยู่ (วันที่/เวลา, การกระทำ, ผู้แก้ไข, AMS, รายละเอียด) รองรับชื่อสถานะคอม `สถานะ pc/nb` และชื่อเดิมที่ระบุใน `DPTC_HEADERS`

คอลัมน์ที่ต้องมี:

- ลำดับ, ประเภท, ผู้รับผิดชอบ, กลุ่ม/ฝ่าย, AMS, ปีที่จัดซื้อ, อายุ PC/NB, สถานะ pc/nb, ผลดำเนินการทดแทน
- จอ, ปีที่จัดซื้อจอ, อายุจอ, สถานะจอ, ผลดำเนินการทดแทนจอ
- หมายเหตุ, เหตุผลความจำเป็นในการขอซื้อ

รองรับชื่อปีซื้อ `ปีที่จัดซื้อ (PC/NB)` และชื่อทดแทนบางแบบด้วย ดูรายการทั้งหมดใน `DPTC_HEADERS` หากมีสองคอลัมน์ที่มีความหมายเดียวกัน แอปจะหยุดให้ตรวจแทนการเดาคอลัมน์

การบันทึกจากแอป:

- เขียน**เฉพาะช่องที่ค่าเปลี่ยนจริง** + ผู้แก้ไข + เวลา ถ้าไม่มีอะไรเปลี่ยนจะไม่เขียนชีตและไม่เพิ่ม `Log`
- สถานะ pc/nb: ค่าที่เลือกแทนสูตรในแถวนั้น (เหมือนเลือกดรอปดาวในชีต) เลือก "อัตโนมัติตามอายุ" เพื่อคืนสูตรเดิม ค่าที่เลือกได้อ่านจากดรอปดาวของชีต
- สถานะจอ ประเภท ต้องเป็นค่าที่ดรอปดาวในชีตอนุญาต ผลทดแทนต้องเป็น รอดำเนินการ / ทดแทนแล้ว / ไม่ทดแทน
- สูตรอายุ (อายุ PC/NB, อายุจอ) ถ้าถูกพิมพ์ทับ แอปจะคืนสูตรเดิมให้ ไม่เขียนทับคอลัมน์ตรวจสอบข้อมูล / Firewall / การส่งมอบ
- `Log` ช่องรายละเอียดเก็บเฉพาะช่องที่เปลี่ยน เช่น `{"สถานะ pc/nb":["ปกติ","ชำรุด"]}`
- เพิ่มรายการใช้แถวว่างแรกที่เตรียมสูตรไว้ (ตอนนี้แถว 59) ไม่ขยายแถวเอง

ข้อจำกัดฝั่งชีต: แท็บ "แผนทดแทนครุภัณฑ์" นับถึงแถว 80 และ "สรุปอัตโนมัติ" นับถึงแถว 100 (แท็บแยกฝ่ายถึง 1100) ถ้าทะเบียนเกินแถว 80 ต้องขยายช่วงสูตรในแท็บนั้น ส่วนแอปนับทุกแถวเสมอ

มีการล็อกตอนบันทึก ตรวจข้อมูลถูกแก้พร้อมกัน ป้องกันรหัสครุภัณฑ์ซ้ำ และบันทึกประวัติใน `Log` ไม่มีปุ่มลบแถว หากบุคคลแก้ชีตโดยตรงพร้อมกับแอป ควรรีเฟรชก่อนบันทึกเสมอ

## พัฒนาและตรวจสอบ

ต้องใช้ Node.js 20 ขึ้นไป ไม่มี dependencies สำหรับ runtime หรือ unit tests

```sh
npm test
npm run build
```

แก้ไฟล์ใน `web/` แล้ว build ใหม่ อย่าแก้ไฟล์รวมโดยตรง สคริปต์สร้างทั้ง `index.html` และ `apps-script/Index.html` จากต้นฉบับชุดเดียวกัน

- `web/domain.js` — กฎการนับและคำนวณ
- `web/app.js`, `web/styles.css` — หน้าจอและการทำงาน
- `web/snapshot.js` — ข้อมูลจริงจากชีต (ไม่มีชื่อบุคคล) สำหรับหน้าเว็บสาธารณะ
- `web/demo.js` — ชุดข้อมูลนิรนามสำหรับ unit test
- `apps-script/Code.gs` — อ่าน/เขียนชีต ตรวจสิทธิ์ และบันทึกประวัติ
- `tests/` — ตรวจยอดแยกฝ่าย แผน 6 ปี ขอบเขตอายุ และการบันทึกผ่าน backend จำลอง รวม `sheet-replica.test.mjs` ที่จำลองชีต `2569+จอ` ทั้งสูตร ดรอปดาว และ `Log` (ข้อมูลจาก `web/snapshot.js` ไม่มีชื่อบุคคล)

ไม่เก็บ Script Properties, `.clasp.json`, `.env`, ข้อมูลจริง หรือรหัสเข้าใช้งานใน repository นี้
